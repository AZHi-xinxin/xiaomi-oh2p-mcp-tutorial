# 第一步：准备，先不要刷

需要一只底部铭牌明确为 **OH2P** 的 Xiaomi 智能音箱 Pro、一根可传数据的 Type-C 线、音箱原电源，以及一台常开 Linux 电脑。刷机电脑和常开电脑可以是同一台，也可以分开。原厂米家配网先做好，确认普通小爱功能可用。

刷完后日常通过 Wi-Fi，不需要 USB 线；常开电脑需要联网且不休眠。手机 Orbis 是对话与工具客户端，不负责音箱固件烧录。

## 先记录，而不是凭记忆填

| 材料 | 人类到哪里看 |
| --- | --- |
| 型号、当前固件 | 音箱铭牌；米家设备设置 → 设备信息/固件版本 |
| 音箱局域网 IP | 路由器后台设备列表，按名称/MAC 对照；可保留 DHCP 租约 |
| 主机 IP / 用户名 | Linux 设置 → 网络；终端 `whoami` |
| TTS 服务参数 | 自己语音服务商控制台：API Key、你有权用的 voice ID、真实模型 ID |
| SSH 管理密钥 | 在常开电脑生成；私钥始终留在那里，公钥用于自己的补丁 |
| 两份系统槽位备份 | 刷机前读取并核验；至少保留已知能启动的原厂槽位 |

要改固件有损坏设备的实际风险。型号、分区、镜像来源对不上时就停在核验阶段，不用“强制刷入”试运气。已经能登录 SSH、音频正常时，无需重新刷。

## 信息和凭据不要混

音箱 SSH 密钥用于电脑登录音箱；TTS key 用于合成声音；MCP token 用于手机访问你的工具；Orbis 语音事件绑定 token 则是另一项可选凭据。它们都不应让 AI 在聊天里打印。

先部署 MCP 功能可不用云 ASR、不运行麦克风监听。自定义声音会把本次播报文字发给 TTS 服务。进阶语音的数据去向见第 4 篇，不能把整套称为全离线。
